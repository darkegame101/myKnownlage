## What I Have Learned
- **Maven Architecture & Purpose**: Role of Apache Maven as a build automation and project management tool for Java; comparison with manual classpath management.
- **POM Configuration (`pom.xml`)**: Structure of Project Object Model, GAV coordinates (`groupId`, `artifactId`, `version`), project metadata.
- **Standard Directory Layout**:
  - `src/main/java`: Application source code.
  - `src/main/resources`: Resource files, configuration properties.
  - `src/test/java`: Test code and test suites.
  - `src/test/resources`: Test fixtures and test configuration.
  - `target/`: Generated bytecode, compiled classes, and packaged archives (`.jar`, `.war`).
- **Dependency Management**: Adding `<dependencies>` and `<dependency>` blocks, retrieving libraries automatically from Maven Central.
- **Maven Repositories**: Distinction between Local repository (`~/.m2/repository`), Central repository, and Remote repositories.
- **Project Packaging Types**: Standalone `.jar` archives, Java Web `.war` archives, and parent `.pom` packaging.
- **Multi-Module Projects**: Configuring parent POM with `<modules>` / `<module>`, inheriting dependencies, modularizing enterprise code into components.
- **Testing Lifecycle**: Executing unit tests and test suites via Maven test execution phase.

## What I Understand
- How Maven automatically resolves and downloads dependencies from remote repositories to the local `~/.m2` cache to eliminate manual JAR downloading.
- Standard directory convention ("Convention over Configuration") allowing any developer or CI tool to build the project without custom scripts.
- Parent-child inheritance mechanism in multi-module POMs for centralizing version control and dependencies across sub-projects.
- How the test phase automatically compiles and runs test cases in `src/test/java` before packaging.

## What I Can Do
- Create standard single-module Maven projects in Eclipse/IDE.
- Configure `pom.xml` to import dependencies (JDBC drivers, UI libraries, testing tools).
- Structure and configure multi-module Maven projects with parent-child POM hierarchy.
- Configure packaging for Java console, Swing GUI, and Web applications.
- Run automated test cases using Maven test runner.

## What I Cannot Yet Do
- Execute complex build commands and lifecycle phases purely from command line interface (`mvn clean package -Pprofile -DskipTests`) without IDE automation.
- Configure custom plugins and plugin executions (e.g. `maven-compiler-plugin`, `maven-shade-plugin`, `maven-surefire-plugin` custom configuration).
- Manage complex dependency scopes (`provided`, `runtime`, `system`, `import`) and resolve transitive dependency conflicts using exclusions.
- Setup `<dependencyManagement>` blocks for multi-module version convergence.
- Configure deployment to private Nexus or Artifactory repositories.
